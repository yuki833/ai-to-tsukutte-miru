## この記事で分かること

![この記事で分かる全体の流れ、AIの役割、人の役割](/images/articles/ai-blog/01-guide.svg)

この記事は、**AIを使ってWebサイトを作ってみたい人**や、**AIが制作のどこまで手伝えるのか知りたい人**を対象にしています。

この記事を読むと、次の3点が分かります。

- ブログの企画から公開までの全体工程
- ChatGPTとCodexに任せた作業
- AIには任せず、人が操作・判断した作業

今回は、WordPressなどの完成済みブログサービスを使わず、AIにコード作成を手伝ってもらいました。完成したブログサイトは、[AIと、つくってみる。](https://ai-to-tsukutte-miru.pages.dev/)で公開しています。

ブログを始めた理由は、別記事の[AIを学びながら、発信してみることにした](/articles/why-start-ai-blog/)にまとめました。

## ブログを公開するまでの全体像

![企画、環境準備、制作、確認、公開という5段階の工程](/images/articles/ai-blog/02-flow.svg)

今回の制作は、次の5段階で進めました。

1. ChatGPTとブログの目的や読者を決める
2. Codexでパソコンの開発環境を確認する
3. Codexがブログのコードと記事管理機能を作る
4. Codexがパソコンとスマートフォンの表示を確認する
5. 人がGitHubとCloudflareを認証し、ブログサイトを公開する

最初に全体工程を決めたことで、「今は何をしているのか」「次に何が必要なのか」を確認しながら進められました。

## ChatGPT・Codex・人の役割を分けた

![ChatGPTは企画、Codexは制作、人は判断と認証を担当](/images/articles/ai-blog/03-roles.svg)

いきなりCodexへ「ブログを作って」と指示したわけではありません。まず、ChatGPTとブログの目的、想定読者、記事構成、技術候補を整理しました。

当初はClaudeでサイトを作る案もありました。しかし、CodexがローカルPCのファイル編集やコマンド実行、エラー確認までできると分かり、今回の実装にはCodexを使いました。

役割分担は次のとおりです。

| 担当 | 主な作業 |
| --- | --- |
| ChatGPT | ブログの企画、読者設定、章立て、引き継ぎ内容の整理 |
| Codex | 環境確認、コード作成、ファイル編集、ビルド、表示確認 |
| 人 | 方針決定、ソフトのインストール、ログイン、認証、公開範囲の判断 |

人がログインや認証を担当した理由は、アカウントの所有者しか本人確認や権限付与を行えないからです。AIが勝手に外部サービスへアクセスしないことは、安全面でも重要です。

## 制作に必要な環境を準備した

![VS Code、Node.js、Git、GitHubという開発環境](/images/articles/ai-blog/04-setup.svg)

Codexがパソコンの環境を確認したところ、VS Codeは利用できましたが、Node.jsとGitは未導入でした。

- **VS Code**：コードや記事を編集するアプリ
- **Node.js**：Astroなどの開発ツールを動かす実行環境
- **npm**：制作に必要なプログラムを管理する仕組み
- **Git**：コードの変更履歴を保存する仕組み
- **GitHub**：コードと変更履歴をオンラインで保管するサービス

Codexはインストール状況と公式の入手先を確認しました。私は、Node.jsとGitのインストーラーを開き、PCへの変更を許可しました。ソフトのインストールはパソコン全体へ影響するため、利用者本人の確認が必要です。

Node.jsを導入した直後は、起動済みのアプリが新しい設定を認識しませんでした。アプリを開き直すと、Node.jsとnpmを使用できるようになりました。

## AstroとMarkdownで記事管理の仕組みを作った

![Markdown、Astro、GitHub、Cloudflare Pagesのつながり](/images/articles/ai-blog/05-stack.svg)

ChatGPTが挙げた技術候補をCodexと確認し、次の構成を採用しました。

- **Astro**：ブログサイトのページを生成する
- **Markdown**：記事をファイルとして保存する
- **GitHub**：サイトのコードと記事を保管する
- **Cloudflare Pages**：生成したブログサイトをインターネットへ公開する

このブログは、現時点ではデータベースを使っていません。私がMarkdownファイルを1つ追加すると、Astroが新しい記事ページを生成します。

Markdownを選んだ主な理由は、データベース料金が不要で、記事と変更履歴をGitHubでまとめて管理できるからです。一方、スマートフォンからの投稿や複数人での編集が必要になった場合は、CMSの導入を検討します。

Codexは、トップページ、記事一覧、記事詳細、カテゴリー、About、AIラボ構想の各ページを作りました。

## デザインを作り、画面表示を確認した

![パソコンとスマートフォンでサイトを確認する図](/images/articles/ai-blog/06-build.svg)

私は、Codexへ次の条件を伝えました。

- 初心者が読みやすい
- 記事を主役にする
- 派手すぎない
- 少しだけAIやテクノロジーらしさを出す
- スマートフォンでも読みやすくする

Codexは、白を基調に、緑と青紫をアクセントにしたデザインを提案しました。さらに、画面幅に応じてレイアウトが変わるようにコードを作りました。

制作後、Codexは全ページを「ビルド」しました。ビルドとは、AstroのコードとMarkdown記事を、ブラウザで表示できる完成済みファイルへ変換する処理です。

Codexは、パソコン表示と幅390pxのスマートフォン表示を確認しました。ページ全体の横はみ出しや、ブラウザに表示されるエラーがないことも確認できました。

## GitHubとCloudflare Pagesで公開した

![ブログ公開の達成結果と次に取り組むこと](/images/articles/ai-blog/07-result.svg)

Codexがコードを完成させた後、私はGitHubの公開リポジトリを作り、Gitの認証を許可しました。公開リポジトリではコードを誰でも閲覧できるため、メールアドレス、パスワード、APIキーなどの秘密情報が含まれていないことを確認しました。

次に、私はCloudflare Pagesへログインし、ブログ用のGitHubリポジトリだけを接続しました。外部サービスへコードを読む権限を渡す操作なので、対象を自分で確認する必要があります。

Cloudflare Pagesには、次の値を設定しました。

- 本番ブランチ：`main`
- ビルドコマンド：`npm run build`
- 公開フォルダ：`dist`

最初の認証では、GitHubアプリの内容を再確認するよう表示されました。私がブログ用リポジトリを選び直して認証すると、Cloudflare Pagesのビルドが成功しました。

### ゴールの達成結果

| ゴール | 結果 | 達成方法 |
| --- | --- | --- |
| ブログサイトをインターネットへ公開する | 達成 | Cloudflare Pagesの無料URLで公開 |
| 新しい記事を追加できるようにする | 達成 | Markdownファイルを追加すると記事ページを生成 |
| スマートフォンで読みやすくする | 達成 | レスポンシブ対応と幅390pxでの表示確認 |
| 低コストで運営する | 達成 | Astro、GitHub、Cloudflare Pagesの無料範囲を利用 |
| 将来の機能追加に備える | 達成 | ページやCMSを後から追加できるAstroを採用 |

今回のゴールだった**「AIと一緒に、記事を追加できるブログサイトをインターネットへ公開すること」**は達成できました。

次回からは、「はじめてのAI」や「仕事で使う」をテーマに、読者が実際に試せる記事を追加します。独自ドメインは、ブログ名と運営方針が固まった段階で改めて検討します。

AIができたこと、人が行ったこと、制作中の失敗から学んだことは、[AIとブログを作って分かった、人がやるべきこと](/articles/ai-blog-review/)にまとめています。
