![このガイドのゴールは、AIと一緒に自分のブログサイトを作って公開すること](/images/articles/ai-blog/01-guide.svg)

この記事は、**AIと一緒に自分のブログサイトを作りたい人**のための実践ガイドです。Windowsパソコンを使い、できるだけ費用をかけずにブログを公開したい人を想定しています。

この記事を順番に進めると、次のことができるようになります。

- ブログサイトを企画して、必要な開発環境を構築する
- AIへ渡すプロンプトを使って、ブログサイトを作成する
- GitHubへコードを保存し、Cloudflare Pagesで公開する

この記事を表示している**「AIと、つくってみる。」が、今回AIと一緒に作ったブログサイトです。**

私は、ChatGPTを企画の相談相手、Codexを実装担当として使いました。ソフトのインストールやアカウント認証など、本人の許可が必要な操作は私が行いました。

> AIサービスの画面や設定名は更新される場合があります。画面が記事と違う場合は、表示されている権限や料金を確認してから進めてください。

## ブログを公開するまでの6ステップ

![ブログを企画し、開発環境を構築し、技術を決め、サイトを作成し、GitHubで管理してCloudflareで公開する6工程](/images/articles/ai-blog/02-flow.svg)

今回の制作工程は、次の6ステップです。以下の章番号と工程番号は一致しています。

1. **ブログを企画する**
2. **開発環境を構築する**
3. **技術構成を決める**
4. **ブログサイトを作成する**
5. **GitHubで管理する**
6. **Cloudflare Pagesで公開する**

STEP 1ではChatGPTを使い、STEP 2以降では主にCodexを使います。ChatGPTで整理した企画情報は、引き継ぎ資料としてCodexへ連携します。

## STEP 1｜ブログを企画する

![ChatGPTは企画、Codexはサイト作成、人は判断と認証を担当する](/images/articles/ai-blog/03-roles.svg)

最初に、ChatGPTとブログの目的、読者、発信内容を整理します。ここが曖昧だと、AIがきれいなサイトを作っても、誰のためのブログか分からなくなります。

### ChatGPTへ入力するプロンプト

次の文章の`［　］`を、自分の内容へ置き換えて使えます。

```text
AIを使って、自分のブログサイトを作りたいです。

ブログを始める目的：
・［例：AIについて学んだことを記録する］
・［例：初心者にも分かりやすく発信する］
・［例：将来の仕事や活動につなげる］

想定読者：
［例：AIに興味はあるが、何から始めればよいか分からない社会人］

発信したい内容：
［例：AIの基本、仕事での使い方、AIツール、制作記録］

この情報をもとに、次の項目を初心者にも分かる言葉で整理してください。
1. ブログのコンセプト
2. 読者が得られること
3. カテゴリー案
4. 最初の記事案
5. サイト制作AIへ渡す引き継ぎ資料
不足する情報があれば、先に質問してください。
```

### AIから返ってきた結果

ChatGPTは、私の回答をもとに「自分自身もAIを学び、実際に使った過程を初心者向けに共有する」というコンセプトを整理しました。また、第一弾の記事として「AIを使って自分のブログサイトを作ってみた」を提案しました。

ChatGPTは、目的、読者、デザイン条件、技術候補、完成条件を1つの引き継ぎ資料へまとめました。私は、その資料をCodexへ渡しました。

### 人が判断すること

ブログの目的と読者は、運営者本人が決めます。AIは選択肢を提案できますが、「誰に何を届けたいか」について責任を持つのは運営者だからです。

### STEP 1の完了チェック

- ブログを始める目的を文章にできた
- 想定読者を具体的に決めた
- 発信するカテゴリーを決めた
- Codexへ渡す引き継ぎ資料を用意できた

## STEP 2｜開発環境を構築する

![自分、Windowsパソコン、VS Code、Node.js、npm、Astro、Git、GitHub、Cloudflare Pages、読者の関連図](/images/articles/ai-blog/04-setup.svg)

次に、ブログサイトを作成するための開発環境をWindowsパソコンへ構築します。

私は、以前からVS Codeをインストールしていました。一方、Node.jsとGitは未導入だったため、この工程でインストールしました。

関連図のとおり、VS Code、Node.js、npm、Astro、Gitは自分のパソコン上で動きます。GitHubとCloudflare Pagesはインターネット上のサービスです。

### Codexへ入力するプロンプト

```text
Windowsパソコンで、Astroを使ったブログサイトを作ります。
まず開発環境を構築してください。

次の項目が利用できるか確認し、不足しているものを教えてください。
・VS Code
・Node.js
・npm
・Git
・現在の作業フォルダ

確認用コマンドは実行してください。
インストールなど私の操作が必要な場合だけ、
「何をするか」「なぜ必要か」「どこを操作するか」を説明してください。
設定を大きく変更する前には、必ず理由を説明してください。
```

### AIから返ってきた結果

Codexは、Node.js、npm、Git、作業フォルダの状態を順番に調べました。その結果、Node.jsとGitのインストールが必要だと分かりました。

Codexは、Node.jsがAstroを動かす土台であり、npmが必要なプログラムを管理する仕組みだと説明しました。また、Gitはサイトの変更履歴を保存するために必要だと説明しました。

### 人が行う操作

私は、Node.jsとGitを公式サイトからインストールしました。インストールはパソコン全体へ変更を加えるため、所有者本人の許可が必要です。

Node.jsをインストールした直後、起動済みのアプリはNode.jsを認識しませんでした。私はアプリを開き直し、Codexが再度コマンドを実行すると、Node.jsとnpmを使用できました。

### STEP 2の完了チェック

CodexまたはVS Codeのターミナルで、次のコマンドを実行します。

```powershell
node -v
npm -v
git --version
```

3つのコマンドでバージョン番号が表示されれば、開発環境の構築は完了です。

## STEP 3｜技術構成を決める

![Markdown、Astro、GitHub、Cloudflare Pagesのつながり](/images/articles/ai-blog/05-stack.svg)

ブログの目的と開発環境に合う技術構成を決めます。今回は、低コスト、記事の追加しやすさ、将来の拡張性を優先しました。

### Codexへ入力するプロンプト

```text
次の条件に合うブログサイトの技術構成を提案してください。

・できるだけ無料で運営したい
・初心者でも記事を追加しやすくしたい
・スマートフォンで読みやすくしたい
・将来、検索やお問い合わせなどの機能を追加したい
・WordPressなどの完成済みブログサービスは使わない

候補を比較し、それぞれの役割、費用、長所、短所を説明してください。
特定の技術を採用する前に、なぜ今回の目的に合うのかも説明してください。
```

### AIから返ってきた結果

Codexは候補を比較し、次の構成を提案しました。

- **Astro**：ブログサイトのページを生成する
- **Markdown**：記事をファイルとして保存する
- **Git / GitHub**：コードと変更履歴を管理する
- **Cloudflare Pages**：完成したブログサイトを公開する

記事数が少ない初期段階では、データベースを使わず、Markdownファイルで記事を管理する方法がシンプルです。Markdownファイルを1つ追加すると、Astroが記事ページを生成します。

### 人が判断すること

私は、無料で始められることと、後から機能を追加できることを確認して、この構成を採用しました。スマートフォンだけで投稿したい場合や複数人で編集する場合は、将来CMSを追加する予定です。

### STEP 3の完了チェック

- サイトを作る技術を決めた
- 記事を保存する方法を決めた
- コードの管理方法を決めた
- 公開先を決めた
- 各サービスの費用を確認した

## STEP 4｜ブログサイトを作成する

![パソコンとスマートフォンに対応したブログサイトを作成する図](/images/articles/ai-blog/06-build.svg)

ここまでの企画と技術構成をCodexへ渡し、ブログサイトを作成します。

### Codexへ入力するプロンプト

```text
AstroとMarkdownを使って、ブログサイトを作成してください。

サイトの目的：
AIに興味はあるけれど何から始めればよいか分からない人が、
AIを実際に使えるようになるための情報を発信する。

必要なページ：
・トップページ
・記事一覧ページ
・記事詳細ページ
・カテゴリー別ページ
・Aboutページ

デザイン条件：
・シンプルで読みやすい
・記事を主役にする
・初心者が親しみやすい
・派手すぎない
・少しだけAIやテクノロジーらしさを出す
・スマートフォンにも対応する

記事はMarkdownファイルで追加できるようにしてください。
いきなりすべてを作らず、最初に作成するページとファイル構成を説明してください。
実装後はビルドを実行し、エラーと画面の横はみ出しがないか確認してください。
```

### AIから返ってきた結果

CodexはAstroプロジェクトを作成し、共通レイアウト、ヘッダー、フッター、記事カードを部品として実装しました。さらに、Markdown記事から記事一覧と記事詳細を自動生成する仕組みを作りました。

最初のデザインは、白を基調に、緑と青紫をアクセントにしたものでした。その後、ブログの目的を「初心者の学習記録」から「読者がAIを使えるようになる実践ブログ」へ見直し、トップページとカテゴリーを更新しました。

Codexは`npm run build`を実行し、すべてのページを生成できることを確認しました。スマートフォン対応は、ブログサイト作成の完了条件として同じ工程内で確認しています。

### 人が判断すること

私は、サイトの文章、カテゴリー、色、将来のAIラボ構想が目的と合っているかを確認しました。デザインの好みや、読者へ伝えたい内容の最終判断は運営者が行います。

### STEP 4の完了チェック

```powershell
npm run build
npm run dev
```

ビルドが成功し、ターミナルに表示されたローカルURLをブラウザで開ければ、ブログサイトの作成は完了です。トップ、記事一覧、記事詳細をパソコンとスマートフォンの両方で確認します。

## STEP 5｜GitHubで管理する

![VS Codeで変更したファイルをGitで記録し、GitHubへ送る流れ](/images/articles/ai-blog/07-github.svg)

完成したブログサイトのコードと変更履歴をGitHubで管理します。

### Codexへ入力するプロンプト

```text
このブログプロジェクトをGitで管理し、GitHubへ登録する準備をしてください。

次の作業を行ってください。
・秘密情報や個人情報が含まれていないか確認する
・不要なファイルをGitHubへ送らないための.gitignoreを確認する
・Gitリポジトリを初期化する
・現在のファイルを最初の変更履歴として保存する

GitHubへのログイン、リポジトリ作成、認証など、
私の操作が必要なところで具体的に案内してください。
公開リポジトリと非公開リポジトリの違いも説明してください。
```

### AIから返ってきた結果

Codexは、公開してはいけない情報がコードに含まれていないことと、`node_modules`などの不要なファイルがGitの対象外になっていることを確認しました。その後、変更履歴を作成しました。

### 人が行う操作

私はGitHubへログインし、ブログ用の公開リポジトリを作成しました。公開リポジトリを選ぶとコードを誰でも閲覧できるため、メールアドレス、パスワード、APIキーなどが含まれていないことを確認する必要があります。

GitHubの認証画面が表示されたとき、私はGit Credential Managerへ必要な権限を許可しました。Codexの作業環境からGitHubへ送信できない場合は、VS Codeのターミナルで次のコマンドを実行しました。

```powershell
git push origin main
```

### STEP 5の完了チェック

GitHubのリポジトリをブラウザで開き、AstroのファイルやMarkdown記事が表示されていれば、GitHubへの登録は完了です。

## STEP 6｜Cloudflare Pagesで公開する

![ブログサイトの公開ゴールと次に取り組む内容](/images/articles/ai-blog/07-result.svg)

最後に、GitHubのコードをCloudflare Pagesへ接続し、ブログサイトをインターネットへ公開します。

### Codexへ入力するプロンプト

```text
GitHubに登録したAstroブログを、Cloudflare Pagesで公開したいです。

初心者向けに、次の内容を順番に案内してください。
・CloudflareとGitHubを安全に連携する方法
・許可するリポジトリの範囲
・本番ブランチ
・ビルドコマンド
・公開フォルダ
・公開後の確認項目

私がログインや認証を行う必要がある箇所では、
なぜ本人の操作が必要なのかも説明してください。
有料機能を選ぶ前には必ず知らせてください。
```

### AIから返ってきた結果

CodexはCloudflare Pagesの設定画面を確認し、次の値を案内しました。

- 本番ブランチ：`main`
- ビルドコマンド：`npm run build`
- 公開フォルダ：`dist`

### 人が行う操作

私はCloudflareへログインし、ブログ用のGitHubリポジトリだけを連携対象にしました。Cloudflareへコードを読む権限を渡すため、アカウント所有者が対象と権限を確認する必要があります。

最初の認証では、GitHubアプリの内容を再確認するよう表示されました。私はブログ用リポジトリを選び直して認証し、Cloudflare Pagesのビルドを開始しました。

ビルドが成功し、このブログサイトを次のURLで公開できました。

[https://ai-to-tsukutte-miru.pages.dev/](https://ai-to-tsukutte-miru.pages.dev/)

### ゴールの達成結果

| ゴール | 結果 | 達成方法 |
| --- | --- | --- |
| ブログサイトをインターネットへ公開する | 達成 | Cloudflare Pagesの無料URLで公開 |
| 新しい記事を追加できるようにする | 達成 | Markdownファイルから記事ページを生成 |
| スマートフォンで読みやすくする | 達成 | レスポンシブ対応を実装して表示を確認 |
| 低コストで運営する | 達成 | Astro、GitHub、Cloudflare Pagesの無料範囲を利用 |
| 将来の機能追加に備える | 達成 | ページやCMSを後から追加できるAstroを採用 |

今回のゴールだった**「AIと一緒に、記事を追加できるブログサイトをインターネットへ公開すること」**は達成できました。

### STEP 6の完了チェックと次回

Cloudflare Pagesが発行したURLを開き、トップページと記事ページが表示されれば公開完了です。GitHubへ新しい変更を送ると、Cloudflare Pagesがブログサイトを自動更新します。

次回からは、「はじめてのAI」や「仕事で使う」をテーマに、読者が同じ操作を試せる記事を追加します。独自ドメインは、ブログ名と運営方針が固まった段階で改めて検討します。

制作中の失敗と、人が操作する必要があった理由は、[AIとブログを作って分かった、人がやるべきこと](/articles/ai-blog-review/)にまとめています。
